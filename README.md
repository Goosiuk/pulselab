# PulseLab

Небольшой монитор HTTP-сервиса на Python. Проверяет статус и время ответа, сохраняет результаты в JSONL и считает долю успешных проверок.

Нужен Python 3.12. Дополнительных Python-пакетов нет. Для запуска сервиса в контейнере нужен Docker.

## Запуск

Все команды выполняются из корня проекта.

```bash
python3 -m venv .venv
source .venv/bin/activate
docker build -t pulselab:local .
docker run --init -d --name pulselab-demo -p 127.0.0.1:8088:8765 pulselab:local
python probe.py
python monitor.py --url http://127.0.0.1:8088/health --count 5 --out checks.jsonl
```

Если контейнер уже создан, вместо повторного `docker run` используется `docker start pulselab-demo`. Остановка — `docker stop pulselab-demo`.

Монитор работает на компьютере, сервис — в контейнере. Порт 8088 компьютера перенаправляется на порт 8765 контейнера. В образ копируется только `lab_service.py`; запуск выполняется от пользователя с UID 10001.

## Без Docker

В одном терминале:

```bash
python lab_service.py --mode healthy --port 8765
```

В другом:

```bash
python monitor.py --url http://127.0.0.1:8765/health --count 5 --out checks.jsonl
```

Режим `error` возвращает 503, `slow --delay 1.5` задерживает ответ. Для смены режима сервис нужно остановить и запустить с другими параметрами. `probe.py` по умолчанию проверяет контейнер на порту 8088.

## Монитор

Параметры: `--url`, `--timeout` в секундах, `--count`, `--interval` в секундах, `--out` — файл JSONL. Сводка относится к текущему запуску. Старые записи файла сохраняются.

Пример результата:

```json
{"url":"http://127.0.0.1:8088/health","status_code":200,"ok":true,"elapsed_ms":12.5,"error":null}
```

Число 12.5 здесь приведено для примера. Успех — итоговый HTTP-статус 200–299. При отказе подключения или таймауте `status_code` равен `null`. Код завершения монитора — 0, если все пробы успешны, иначе 1.

## Проверки

```bash
python -m unittest -v
```

Девять тестов: ответы 200/404/503, таймаут, отказ подключения, три случая расчёта доли успешных проб и добавление записей JSONL. HTTP-тесты сами запускают локальный сервер на свободном порту.

Остановка и восстановление контейнера описаны в [INCIDENT.md](INCIDENT.md). Записи проверок находятся в [evidence](evidence/2026-11-07-docker/events.json).

## Ограничения

Одна точка наблюдения и один URL. Проверяется статус, а не содержание ответа. Время измеряется до получения статуса и заголовков. Клиент следует перенаправлениям; таймаут ограничивает отдельные сетевые операции, а не весь запрос целиком. Доля успешных проб не равна точному времени доступности между проверками. Автоматических перезапусков, алертов и ротации журнала нет.
